# Philosophy

Sentinel is **not an application**.

Sentinel is a **platform**.

Therefore every screen must feel like it belongs to one product.

No matter who develops it.

---

# Golden Rules

## Rule 1

Everything is a Component.

## Rule 2

---

## Rule 3

No duplicate components.

---

## Rule 4

If a component is used 3 times

→ Make it reusable.

# I would add one thing that I think will make Sentinel feel like a premium product

Don't think in terms of **screens**.

Think in terms of **workspaces**.

For example:

## Overview Workspace

- "How healthy is my project?"

## Investigation Workspace

- "Why did this issue happen?"

## Improvement Workspace

- "What can I safely fix?"

## Compliance Workspace

- "Do we satisfy our organization's rules?"

## Reporting Workspace

- "What changed over time?"

Each workspace can reuse the same components (cards, charts, diff viewers, inspectors), but arrange them differently depending on the user's goal.

This is how tools like Figma, GitHub, and Docker Desktop stay coherent even as they grow.

# One thing I'd change before writing any code

If I were leading this project, I would **stop writing specifications after this** and spend several weeks creating a **high-fidelity interactive prototype in Figma**.

Not static screenshots.

A clickable prototype with:

- Opening a project
- Running a scan
- Viewing issues
- Previewing a fix
- Comparing diffs
- Installing a plugin
- Importing a rule pack

Then I'd put that prototype in front of 10–20 real C/C++ developers (embedded engineers, backend developers, leads) and watch them use it without explanation.

The insights from those sessions would be far more valuable than another 50 pages of specifications, and they'd shape the product before a single line of production code is written. That's the approach I'd take if the goal is to build something developers genuinely choose to use.
